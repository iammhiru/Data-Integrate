THAY ĐỔI SO VỚI PROPOSAL BAN ĐẦU
-------------------------------------------------------------------------------
- Bỏ Apache Flink.
- Spark Structured Streaming: đọc Kafka, chuẩn hoá/validate, ghi raw vào MinIO
  và tính metric realtime (window ngắn) cho dashboard giám sát.
- Spark Batch: đọc raw từ MinIO, dedup + enrich + tổng hợp theo giờ/ngày/ca,
  tính downtime, quality, OEE, data quality rồi ghi (upsert) vào PostgreSQL.
- Kiến trúc dạng Lambda: speed layer (Spark Streaming) + batch layer (Spark
  Batch) dùng chung một engine, chung code transform.

 2. NGUỒN DỮ LIỆU (DATA SOURCES)
===============================================================================

2.1 Machine Telemetry (Kepware / OPC UA) - tần suất 1-10 event/s/máy
-------------------------------------------------------------------------------
 Dữ liệu gốc dạng key-value OPC UA, node id ví dụ:
   ns=2;s=Line1.M001.Temperature
 Field           Kiểu        Mô tả
 timestamp       timestamp   Thời điểm phát sinh (source timestamp OPC UA)
 machineId       string      ID máy (gốc có thể là machine_id / equipment_id)
 temperature     double      Nhiệt độ (°C)
 pressure        double      Áp suất (bar)
 speed           double      Tốc độ (rpm / units per min)
 energy          double      Điện năng tiêu thụ (kWh)
 status          string      RUNNING | IDLE | STOPPED
 operatingMode   string      AUTO | MANUAL | MAINTENANCE
 (+ các thuộc tính mở rộng để đạt 10-20 attribute: vibration, current,
  voltage, humidity, spindleLoad, toolWear, ...)

2.2 Production Events (Production Simulator) - JSON event
-------------------------------------------------------------------------------
 Field            Kiểu        Mô tả
 timestamp        timestamp   Thời điểm phát sinh
 machineCode      string      ID máy (tên gốc khác: cần map -> machineId)
 productId        string      Sản phẩm
 productionOrder  string      Lệnh sản xuất
 quantity         int         Sản lượng trong event
 goodQuantity     int         Số lượng đạt
 rejectQuantity   int         Số lượng NG
 shift            string      Ca (A | B | C)
 idealCycleTime   double      Thời gian chu kỳ lý tưởng (giây/sản phẩm)

2.3 Quality / Inspection Events (Quality Simulator) - JSON event
-------------------------------------------------------------------------------
 Field            Kiểu        Mô tả
 timestamp        timestamp   Thời điểm kiểm tra
 equipment_id     string      ID máy (tên gốc khác: cần map -> machineId)
 productId        string      Sản phẩm
 inspectionId     string      ID lần kiểm tra
 result           string      PASS | FAIL
 defectType       string      SCRATCH | DENT | DIMENSION | COLOR | NONE ...
 quantity         int         Số lượng được kiểm tra
 rejectQuantity   int         Số lượng lỗi

2.4 Master Data (PostgreSQL, seed từ CSV)
-------------------------------------------------------------------------------
 machine, product, shift, machine_id_mapping (xem mục 4.3)


===============================================================================
 3. EVENT SCHEMA CHUẨN (ENVELOPE) - output của Middleware
===============================================================================

 {
   "eventId":     "uuid",                    -- dùng để phát hiện duplicate
   "eventType":   "machine.telemetry" | "production.event" | "quality.event",
   "source":      "kepware-opcua" | "production-sim" | "quality-sim",
   "machineId":   "M001",                    -- ID đã chuẩn hoá
   "timestamp":   "2026-10-05T22:30:01.123Z",-- event time (UTC, ISO-8601)
   "ingestedAt":  "2026-10-05T22:30:01.180Z",-- middleware publish time
   "schemaVersion": 1,
   "payload": { ...các field nghiệp vụ theo eventType... }
 }

 Quy tắc chuẩn hoá trong Middleware:
 - machine_id / machineCode / equipment_id  -> machineId (tra bảng mapping)
 - camelCase cho mọi field, timestamp -> UTC ISO-8601
 - giá trị thiếu giữ là null (KHÔNG tự điền), để Spark ghi nhận missing data
 - ingestedAt dùng để đo latency; Spark thêm processedAt

4.2 MinIO - Data Lake (bucket: smart-factory)
-------------------------------------------------------------------------------
 s3a://smart-factory/
   raw/machine_telemetry/date=YYYY-MM-DD/hour=HH/part-*.parquet
   raw/production/date=YYYY-MM-DD/hour=HH/part-*.parquet
   raw/quality/date=YYYY-MM-DD/hour=HH/part-*.parquet
   invalid/<eventType>/date=YYYY-MM-DD/part-*.parquet   (event lỗi validate)
   checkpoints/<job-name>/                               (Spark checkpoint)

 Cột của raw Parquet:
   eventId, eventType, source, machineId, eventTime, ingestedAt, schemaVersion,
   payload (JSON string gốc, batch job tự parse), kafkaTopic, kafkaPartition,
   kafkaOffset, kafkaTimestamp, processedAt, date, hour
 Cột của invalid Parquet: như trên + invalidReason, rawValue (message gốc)

 5. LUỒNG DỮ LIỆU
===============================================================================

 [Kepware OPC UA] --> [Middleware] --+
 [Production Sim] -------------------+--> [Kafka] --> [Spark Structured Streaming]
 [Quality Sim] ----------------------+                    |          |         |
                                                          |          |         |
                         (A) raw Parquet  <---------------+          |         |
                             MinIO                                   |         |
                               |              (B) realtime-metrics --+         |
                               |                  Kafka -> .NET -> WebSocket   |
                               |                  -> UI Realtime               |
                               |              (B') machine_status_current,     |
                               |                   machine_metric_1m --> PG <--+
                               v
                    (C) [Spark Batch] -- hourly/daily --> PostgreSQL
                                                              |
                                          .NET REST API <-----+--> Dashboard

5.1 Luồng A - Raw ingest (Spark Streaming, trigger 1 phút)  [spark/apps/kafka_to_minio.py]
-------------------------------------------------------------------------------
 Kafka (3 topic) -> parse JSON envelope -> validate schema
   -> valid   : thêm date, hour -> Parquet s3a://.../raw/<type>/
   -> invalid : s3a://.../invalid/ (kèm invalidReason)
 Một streaming query + foreachBatch (đọc Kafka một lần, tách ra nhiều thư mục).
 Không dedup ở đây: raw giữ nguyên để có thể tái xử lý.
 Checkpoint s3a://.../checkpoints/raw-ingest lưu offset -> at-least-once;
 bản ghi trùng do retry được batch job loại theo eventId.

5.2 Luồng B - Realtime metrics  [spark/apps/realtime_metrics.py, service stream-realtime]
-------------------------------------------------------------------------------
 Kafka machine-telemetry + production-events
   -> parse envelope, bỏ event thiếu eventId/machineId/timestamp
   -> withWatermark("eventTime", "30 seconds")
   -> dropDuplicatesWithinWatermark("eventId")
   -> 3 query, output mode update (mỗi trigger phát giá trị mới nhất của window đang mở):
      status_5s      window 5s / máy, trigger 5s:  status mới nhất, avg temperature/
                     pressure/speed, sum energy, sampleCount, missingCount
      metric_1m      window 1 phút / máy, trigger 30s
      production_1m  window 1 phút / máy, trigger 5s: totalQty, good, reject,
                     productionRate (sản phẩm/phút trên phần window đã trôi qua)
   -> Kafka `realtime-metrics` (key machineId, field metricType) -> .NET -> WebSocket -> UI
   -> upsert PostgreSQL: machine_status_current (chỉ ghi đè khi event_time mới hơn),
      machine_metric_1m
 State store RocksDB, checkpoint trên volume dùng chung /opt/spark-checkpoints.
 Mỗi message có emittedAt, maxIngestedAt, latencyMs = emittedAt - maxIngestedAt
 (scripts/measure_latency.py tính avg / p50 / p95 / max).
 Event trễ hơn watermark (30s) bị bỏ khỏi realtime nhưng vẫn có trong raw -> batch
 layer tính lại chính xác.

5.3 Luồng C - Batch analytics (Spark Batch)  [spark/apps/minio_to_postgres.py]
 Đã cài đặt: production_metric, quality_metric, data_quality_metric.
 Chưa cài đặt: downtime_event, oee_metric.
 Late event = ingestedAt - eventTime > 30 giây (tham số --late-threshold-sec).
-------------------------------------------------------------------------------
 Hourly job (chạy lúc HH:15 cho giờ HH-1, chừa thời gian cho late data):
   đọc raw partition date/hour -> dedup theo eventId
   -> enrich với master data (JDBC đọc machine, product, shift)
   -> production_metric, quality_metric, data_quality_metric
 Daily job (chạy 00:30 cho ngày trước, tính lại toàn bộ ngày):
   -> downtime_event: sắp xếp telemetry theo machineId + eventTime,
      dùng window function lag() để phát hiện đổi status, tính duration
   -> oee_metric theo machine / product / shift / date
 Backfill / reprocess: chạy job với tham số --from --to trên dữ liệu MinIO
 (dùng để sinh 30 ngày lịch sử và khi logic thay đổi).
 Ghi PostgreSQL bằng staging table + INSERT ... ON CONFLICT DO UPDATE
 -> chạy lại job không bị trùng (idempotent).

 6. CÔNG THỨC TÍNH
===============================================================================
 Production Rate = Produced Quantity / Operating Time
 Reject Rate     = Reject Quantity / Total Quantity x 100%
 Availability    = Run Time / Planned Production Time
 Performance     = (Ideal Cycle Time x Total Count) / Run Time
 Quality         = Good Count / Total Count
 OEE             = Availability x Performance x Quality
 Data Quality    = Valid Events / Total Events x 100%
 Planned Production Time = shift.planned_minutes - shift.planned_break_minutes
 Run Time        = tổng thời gian status = RUNNING trong planned time
 Downtime        = tổng thời gian status = STOPPED
 Idle Time       = tổng thời gian status = IDLE


===============================================================================
 7. ĐÁNH GIÁ
===============================================================================
 Throughput      : event xử lý thành công / giây (Spark StreamingQueryProgress:
                   processedRowsPerSecond); mục tiêu 500-1.000 event/s
 Latency         : timestamp (generated) -> ingestedAt -> processedAt -> UI
                   báo cáo avg / P95 / max
 Completeness    : số event lưu ở MinIO / số event simulator đã sinh x 100%
 Data quality    : valid / duplicate / invalid / missing / late
 Correctness     : OEE từ Spark batch so với script SQL/Python độc lập trên
                   tập dữ liệu nhỏ (chênh lệch kỳ vọng 0%)
